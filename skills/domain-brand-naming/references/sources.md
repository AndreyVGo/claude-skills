# Источники: что считается доказательством

Доказательства делятся на две группы, и они не равны. Прочитай это до первой проверки.

## Группа A — проверяешь сам в любом режиме кроме офлайна

| Что | Как | Ссылка воспроизводима |
|---|---|---|
| Домен, зоны с RDAP | bootstrap `data.iana.org/rdap/dns.json` → RDAP-сервер зоны | да |
| Домен, зоны без RDAP | WHOIS-43 | **нет**: приводи сервер, дату и сам вывод |
| История домена | `web.archive.org/cdx/search/cdx?url=<домен>&output=json` | да |
| npm | `registry.npmjs.org/<имя>` — 404 = свободно | да |
| PyPI | `pypi.org/pypi/<имя>/json` — 404 = свободно | да |
| GitHub | `api.github.com/users/<имя>` — 404 = свободно | да |
| App Store | `itunes.apple.com/search?term=<имя>&entity=software` | да |
| VK | `vk.com/<имя>` — 404 = свободно | да |
| Пошлины Мадрида | `madrid.wipo.int/feecalcapp/` — принимает GET-параметры | да |

**RDAP есть** для `.com .net .org .br .ai` и большинства новых gTLD.
**RDAP нет** для `.ru .рф .su .eu .us .cn .de .es .io .mx` — только WHOIS-43,
URL для такой проверки не существует в природе. Не выдумывай его и не подставляй
вместо него ссылку на регистратора: она ничего не доказывает.

Скрипт `scripts/check-name.sh` закрывает всю группу A одной командой.

## Группа B — закрыта капчей, логином или JS-рендером

Базы ТЗ (Роспатент/ФИПС, WIPO Global Brand Database, TMview, EUIPO, USPTO),
реестры юрлиц (ЕГРЮЛ и аналоги), Google, Яндекс, Instagram, X, Telegram, Google Play.

- **Режим БРАУЗЕР** — открываешь и проверяешь. Доказательство: цитата страницы
  или скриншот с датой.
- **Режим СЕТЬ** — писать результат права не имеешь. Статус строго «не проверено»
  плюс номер чек-листа из `checklists.md`.

Что проверено запросами и возвращает при попытке автоматизации:

| Источник | Что происходит |
|---|---|
| WIPO Global Brand DB | CAPTCHA (ALTCHA), результатов нет |
| TMview | пустой ответ, hash-роут SPA |
| USPTO tmsearch | только JS-оболочка |
| EUIPO search | HTTP 403 |
| Роспатент searchplatform | React-SPA, полный поиск по регистрации |
| ФИПС открытые реестры | форма POST, GET-ссылки на запрос нет |
| egrul.nalog.ru | CAPTCHA + bot-mitigation |
| google.com/search | 302 → consent.google.com |
| Яндекс | SmartCaptcha на датацентровых IP |

## Ловушки ложного результата

Дают неверный ответ даже в режиме БРАУЗЕР:

- **Instagram** отдаёт HTTP 200 на несуществующий хэндл (login wall);
- **t.me** отдаёт 200 на любой хэндл;
- **Google Play** `/store/search` отдаёт 200 на любой запрос;
- **x.com** агенту обычно не отвечает вовсе;
- **Открытые реестры ФИПС не дают поиска по обозначению** — только выдачу документа
  по известному номеру. Поиск на тождество и сходство — это платная ИПС или заявление
  на предварительный поиск в ФИПС. Никогда не пиши «0 совпадений по ФИПС», если поиск
  шёл не в ИПС.

## Ссылки

- На найденное сходное обозначение ссылайся **по номеру через карточку реестра** —
  карточки стабильны и отдают 200: ФИПС `registers-doc-view`, EUIPO eSearch `#details`,
  WIPO Madrid Monitor `showData.jsp`.
- Ссылку «на поисковый запрос» **не выдумывай**: почти везде это SPA-хэш или сессия.
- Каждая проверка датируется.
- Пошлины, состав Мадридской системы и правила зон проверяй в источнике, а не по
  памяти: меняются несколько раз в год.

## EUIPO API

У EUIPO есть Developer Portal (`dev.euipo.europa.eu`) с Trademark Search API поверх
TMview — 100M+ знаков, 70+ ведомств. Требует Client ID/Secret и одобрения
production-доступа. Это единственный способ сделать блок ТЗ машинно проверяемым,
но ключ заводит пользователь, а не ты. Отсюда вопрос 13 в брифе.
